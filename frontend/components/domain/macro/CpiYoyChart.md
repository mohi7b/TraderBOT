## ۲) انتخاب سری (`pickSeries`) — کدام منبع رسم می‌شود؟

ورودی: همهٔ سری‌های کشور. سه ردهٔ تطبیق به‌ترتیب: **canonical code** → **provider code** (`*_CPI_*`) → **dataset code**.

داخل هر رده:

1. نقاط **آینده** رد می‌شوند (`dateRankOf(lastDate) <= nowRank`؛ جلوی پیش‌بینی سالانهٔ IMF/WB را می‌گیرد).
2. **تازه‌ترین as-of** برنده است؛ در تساوی، سری **رسمی** بر `DERIVED` مقدم است.
3. باند تحمل **۶ ماه** (`PICK_TOLERANCE_MONTHS`): داخل باند فقط برای `CORE_CPI` **کیفیت منبع** حاکم است (P2)،
   وگرنه **کادنس ریزتر** (M > Q > A) ترجیح دارد (P3).

**رتبهٔ کیفیت منبع** (`qualityRankOf`، ۰ = بهتر — آینهٔ picker بک‌اند):

| rank | منبع |
|---|---|
| ۰ | `EUROSTAT` + `HICP_ANR` |
| ۱ | `EUROSTAT` (HICP) |
| ۲ | `FRED` |
| ۳ | `OECD` + `CPI_IDX_TXCP01_NRG` |
| ۵ | سایر |
| ۹ | `DERIVED` (Core مشتق‌شده در `core.db`) |

> نتیجهٔ عملی (نمونه): AUS = BIS پله‌ای که به فصل تجمیع می‌شود (تازه‌ترین) · CAN/JPN = BIS/FRED · TUR Core = مشتق تازه.

## ۳) محاسبهٔ YoY — آیا باید محاسبه شود یا داده خودش نرخ است؟

همهٔ چارت‌ها فقط از **یک دروازه** رد می‌شوند: `seriesYoyPoints(series, { guard: "cpi" })`.

| گام | تابع | قاعده |
|---|---|---|
| ۱ | `isPrecomputedRate(series_kind)` | `rate`/`percent` ⇒ **مقدار خام عیناً YoY** (بدون محاسبه) |
| ۲ | `detectRateLike(history, CPI_RATE_GUARD)` | اگر kind اشتباه باشد ولی **خودِ داده** نرخ‌مانند باشد ⇒ همان مسیر خام |
| ۳ | `computeYoyRows` | `(v_t / v_{سال‌قبل} − 1) × 100` — **تاریخ‌محور** (`priorYearKey`) نه مکان‌محور ⇒ مقاوم به گپ |
| ۴ | `computeAnnualized3m` | `((v_t / v_{t−3})^(4/3) − 1) × 100` — فقط از **سطح**؛ روی سری نرخ خالی است |
| ۵ | `computeAnnualizedQuarterly` | `((v_t / v_{t−1})^4 − 1) × 100` برای سری **فصلی** |

**گارد نرخ‌مانندگی** (`CPI_RATE_GUARD`): `maxRateMedian=60` · `maxPositiveStepShare=0.85` · `minPoints=24`.
شاهد واقعی: کانادا (`BIS`) برچسب `index` داشت ولی داده نرخ بود ⇒ بدون گارد، «7۵٪» رسم می‌شد (باید ۳٪ باشد).

## ۴) کادنس واقعی (P3) — ماهانه، فصلی، و منبع «پله‌ای»

بک‌اند برای هر سری `cadence: { declared, effective, padded, flat_ratio }` می‌دهد.

| حالت | مثال | رفتار چارت |
|---|---|---|
| ماهانه واقعی | USA (FRED)، CAN (BIS) | خط ماهانه، `timeScale.timeVisible=false`، `futureMargin=12` |
| فصلی واقعی | `OECD.AUS.CPI_IDX.Q` | خط فصلی، `timeVisible=true`، `futureMargin=4` |
| **پله‌ای** (`padded=true`) | AUS فعلی = BIS ماهانه که هر فصل تکرار شده (`flat_ratio≈0.696`) | `collapsePaddedRows()`: فقط ماه پایانی فصل (۳/۶/۹/۱۲) با تاریخ `YYYY-Qn` ⇒ **۱۵ ماه در سال اختراع نمی‌شود** |

- `dateRankOf()` تاریخ‌های `YYYY-MM` / `YYYY-Qn` / `YYYY-Sn` / `YYYY` را به یک عدد ماه‌محور تبدیل می‌کند
  (مقایسهٔ رشته‌ای `2026-Q2` با `2026-06` غلط است).
- برای منبع پله‌ای، «۳ماههٔ annualized» از **سطح فصل‌ها** ساخته می‌شود
  (`quarterlyLevelsFromPadded` → `computeAnnualizedQuarterly`)، وگرنه گام‌های صفر نتیجه را بی‌معنا می‌کرد.
- `layoutOverride` دامنه فقط دو کلید می‌دهد (`timeVisible` برای Q و `futureMargin` ۱۲/۴)؛ باقی چینش از **تم**.

## ۵) هدف تورمی (Target) — منبع حقیقت، fallback، و مقیاس

| گام | منبع | جزئیات |
|---|---|---|
| ۱ | `meta` از `GET /api/country/<ISO3>` | جدول `inflation_targets` در `collector/macro/db/macro.db` (۲۳ ردیف) |
| ۲ | fallback کد | `CPI_TARGETS` در `lib/macro/targets.ts` — **آینهٔ DB** برای ۱۹ کشور (اگر API در دسترس نباشد) |
| ۳ | باند نقطه‌ای | هدف‌های نقطه‌ای مثل USA/CAN/JPN به‌صورت `low === high` ذخیره شده‌اند ⇒ سقف = هدف |

**نمایش:** هدف در **ردیف لجند** (سوآچ هم‌رنگ) + لایه `target-band` روی چارت
(باند ⇒ مستطیل کم‌رنگ + دو لبه · نقطه‌ای ⇒ یک خط ضخیم ترنسپرنت — `paintTargetBand`).

⚠️ **باگ رفع‌شده (2026-09-22):** مقیاس قیمت فقط از دادهٔ سری autoscale می‌شد، پس اگر هدف بیرون از دامنهٔ
داده بود **دیده نمی‌شد** (شاهد: چین با تورم ‎−۰٫۸..۱٫۳ و هدف ۳٪). حالا `BaseChart` از
`expandRangeForTarget(min, max, band)` استفاده می‌کند:

```
pad = max(0.5, 1.5 × span)            // span = دامنهٔ دادهٔ پنجرهٔ فعلی
هدف داخل مقیاس می‌آید اگر در [min − pad, max + pad] باشد؛ وگرنه چارت فشرده نمی‌شود.
```

نتیجهٔ سنجیده‌شده: CHN ⇒ `[−0.80 … 3.00]` · TUR ⇒ `[5.00 … 75.45]` · USA ⇒ `[2.00 … 6.41]` · هایپرینفلاسیون (۹۰..۱۰۰ با هدف ۲) ⇒ **بدون فشردگی**.

ترتیب پنل از تم می‌آید: `ids: [iss, trend, momentum, deviation, volatility, pressure, stability]` · `max: 7`.

| # | id | نام کامل | نمایش | خروجی اصلی | رنگ (tone) |
|---|---|---|---|---|---|
| ۱ | `iss` | **ISS — Integrated Inflation Signal** | `Iss ↗↗ 56%` | فلش جامع + درصد پایداری | **پس‌زمینه** = ۴ سطح وضعیت · **متن** = ۳ حالت جهت |
| ۲ | `trend` | Trend (جهت روند) | `▲ up / ▼ down / ■ flat` | امتیاز جهت | آگاه به هدف (بالای هدف: صعود قرمز · نزول سبز …) |
| ۳ | `momentum` | Momentum (مومنتوم) | `+0.23` | Δ1 | مثل trend (آگاه به هدف) |
| ۴ | `deviation` | Deviation (انحراف از میانگین) | `+1.3σ` | z نسبت به میانگین ۱۲دوره | «بالا = نامطلوب» با `bias` |
| ۵ | `volatility` | Volatility (نوسان) | `0.36 ⚠` | σ گام‌ها | `>1.3×` تاریخ ⇒ زرد · وگرنه آبی |
| ۶ | `pressure` | Pressure (فشار تورمی) | `84` | ۰..۱۰۰ | `>65` زرد · `<35` آبی · بین ⇒ خاکستری |
| ۷ | `stability` | Stability (پایداری) | `52` | ۰..۱۰۰ | `>65` سبز · `<35` قرمز · بین ⇒ خاکستری |
| ۸ | `divergence` | Core−Headline Divergence | `+0.4` | gap (واحد درصد) | با `bias` (بالا = نامطلوب) — **در این قالب نمایش داده نمی‌شود** |
| ۹ | `reversal` | Reversal Probability | `36%` | ۰..۹۵٪ | `>60%` زرد · وگرنه آبی — **در این قالب نمایش داده نمی‌شود** |

### ۸٫۱) ابزار مشترک: «جهت اخیر» (`recentDirection`) — منبع حقیقت Trend و ISS

```
d1 = آخرین − دورهٔ قبل            (وزن ۲ · تازه‌ترین اطلاعات)
d3 = آخرین − دورهٔ سه‌قبل         (وزن ۱)
score = (2·d1 + d3) / 3
eps   = max(0.02, σ(Δ12) × 0.35)   // آستانه از نویز واقعی سری
dir   = score > eps ? "up" : score < −eps ? "down" : "flat"
mag   = (|d1| + |d3|) / 2
```

> ⚠️ **درس مهم (باگ واقعی):** قبلاً `trend` از `slope(آخرین ۳ نقطه)` می‌آمد و `ISS` از Δ1/Δ3.
> در کانادا (`… 2.82 → 3.23 → 2.80 → 3.03`) شیب سه‌نقطه‌ای منفی می‌شد (فلش ▼) در حالی که Δ1 و Δ3
> هر دو مثبت بودند (فلش ISS ↗) ⇒ **دو سیگنال متناقض**. حالا هر دو از همین تابع تغذیه می‌شوند
> و اختلاف **از نظر معماری ناممکن** است (بررسی: ۱۷/۱۷ هم‌جهت).

### ۸٫۲) ISS — مؤلفه‌های چهارگانهٔ فلش

| مؤلفه | ورودی | قاعده |
|---|---|---|
| ۱) جهت | `d1`, `d3` | بالا ↑/↗ · پایین ↓/↘ · افقی → |
| ۲) زاویه | `mag` در برابر `max(0.15, σΔ12)` | مومنتوم قوی ⇒ **عمودی** (`↑ ↓`) · ضعیف ⇒ **مورب** (`↗ ↘`) |
| ۳) تعداد (۱..۳) | `slopeIntensity = mean(|slope3|, \|slope6\|) / max(0.03, σΔ12×0.5)` | `<0.6` ⇒ ۱ · `<1.6` ⇒ ۲ · وگرنه ۳ |
| ۴) ضخامت/فشار | `pressure = 0.45·clamp(CV(Δ12)/0.25) + 0.35·clamp(\|z\|/1.6) + 0.20·clamp(\|gap\|/1.0)` | `<0.34` نازک (font 400) · `<0.67` متوسط (600) · وگرنه ضخیم (800) |

- `gap` = فاصلهٔ Core−Headline در آخرین دورهٔ مشترک (اگر سری دوم باند باشد؛ برای سری‌های سطح-شاخص
  نسبی می‌شود: `|mean12| > 50 ⇒ gap/mean×100`).
- **درصد = پایداری روند:** `round(0.6×stability + 0.4×(100 − reversal))` ⇒ ۱۰۰ = پایدار و قابل‌اعتماد.
- **رنگ پس‌زمینه = وضعیت کلی تورم (۴ سطح):** فاصلهٔ فراتر از دامنهٔ هدف (یا `|z|` بدون هدف):

| سطح | معیار (واحد درصد فراتر از هدف) |
|---|---|
| 🟢 سالم (`pos`) | `≤ 0.5` |
| 🟡 هشدار (`warn`) | `≤ 1.5` |
| 🟠 پرخطر (`risk`) | `≤ 3` |
| 🔴 خطرناک (`neg`) | `> 3` |

  بدون دامنهٔ هدف، برش‌های `|z|` = ۰٫۷۵ / ۱٫۵ / ۲٫۲۵. **یک پله ارتقا** اگر `pressure ≥ 0.67` یا `reversal ≥ 60%`.
- **رنگ متن = جهت (۳ حالت)** — دقیقاً همان منطق `trend` (تابع مشترک `toneOfMove`): فقط 🟢/🔴/⚪.

### ۸٫۳) رنگ جهت آگاه به هدف (`toneOfMove`)

| وضعیت آخرین مقدار | حرکت | رنگ |
|---|---|---|
| بالای سقف هدف | نزول ⇒ `pos` (سبز) · صعود ⇒ `neg` (قرمز) |
| زیر کف هدف (ریسک رکود/تورم منفی) | صعود ⇒ `pos` · نزول ⇒ `neg` |
| داخل دامنهٔ هدف | هر حرکت ⇒ `neutral` |
| بدون دامنهٔ هدف | قرارداد `bias`: `up-is-bad` (تورم) ⇒ صعود قرمز · نزول سبز |

> این جدول علت رنگ‌های «غیرشهودی» را توضیح می‌دهد: در چین (زیر هدف، نزولی) `trend` **قرمز** است،
> ولی در آمریکا/ترکیه (بالای هدف، نزولی) **سبز** — هر دو درست‌اند.

### ۸٫۴) فرمول بقیهٔ سیگنال‌ها

| سیگنال | فرمول |
|---|---|
| `trend` | `display = ▲/▼/■` از `dir`؛ `tone = toneOfMove(score, eps, {bias, target, last})` |
| `momentum` | `Δ1 = last − prev1` (نمایش) · `Δ3` در tooltip · `tone = toneOfMove(Δ1, 0.01, …)` |
| `deviation` | `z = (last − mean12) / σ12` · `tone = toneOfDir(z, 0.5, bias)` |
| `volatility` | `σ(Δ12)` (نمایش) · `ratio = σ(Δ12)/σ(Δall)` · `ratio > 1.3 ⇒ ⚠ + warn` |
| `pressure` | `clamp(50 + 20·clamp(z,−2,2) + 15·clamp(dir.score/σ12, −1, 1), 0, 100)` |
| `stability` | `clamp(100 − (σ(Δ12)/σ(Δall)) × 60, 0, 100)` |
| `divergence` | `last_headline − last_core` (هم‌تاریخ‌ترین دورهٔ مشترک) |
| `reversal` | `clamp(10 + 22·|z| + (ناهم‌راستایی slope6 با گام آخر ? 12 : 0), 0, 95)` |

## ۹) منطق رنگ‌ها (چرا این رنگ؟)

منبع حقیقت رنگ بج‌ها: `frontend/lib/chart/colorMath.ts` (`statusBadgePaint`) + `BaseChart.badgePaint`.
هیچ رنگی در کامپوننت هاردکد نیست؛ همه از **اسلات‌های تم** می‌آید.

### ۹٫۱) دو لایهٔ معنایی بج ISS

| لایه | منبع رنگ | معنا |
|---|---|---|
| **پس‌زمینه** | `tone` (۴ سطح وضعیت) با آلفای `statusTint = 0.35` **روی پایهٔ `badgeBg` بقیهٔ بج‌ها** | سالم/هشدار/پرخطر/خطرناک — «حاله»ی ملایم، نه بلوک رنگی |
| **حلقه (حاشیه)** | همان رنگ با آلفای `tint + 0.5 = 0.85` | **رنگ خالص وضعیت**: همین حلقه است که زرد را از نارنجی و نارنجی را از قرمز جدا می‌کند |
| **متن مقدار** | `valueTone` → `valueUp` / `valueDown` / `valueFlat` | فقط **۳ حالت**: سبز `#22c55e` · قرمز `#ff3b30` · سفید `#e2e8f0` |
| **صفحهٔ زیرین متن** | `valuePlate = 0.75` (+ `adaptivePlate` تا ۰٫۸ روی تگ روشن) | متن را «جلوتر» می‌آورد تا رنگش با هیوی وضعیت مخلوط نشود |
| **هالهٔ نور متن** | `text-shadow: 0 0 6px <رنگ خالص جهت>@0.55` | اگر متن برای کنتراست روشن شود، رنگ‌مایهٔ جهت گم نشود |
| **برچسب `Iss`** | `textMuted` تم | خوانا روی هر حاله |

### ۹٫۲) ⚠️ تجربه‌های ثبت‌شده (تکرار نکنید)

1. صفحهٔ زیرین **کم‌آلفا** (مثل ۰٫۴) قرمز را روی تگ زرد به نارنجی/سالمون می‌برد ⇒ صفحه باید تیره بماند.
2. اگر رنگ متن از **نردبان وضعیت** گرفته شود (مثل `signalNeg` سرخابی)، روی تگ زرد روشن و بی‌رنگ می‌شود ⇒ رنگ متن باید از اسلات‌های **جهت** بیاید.
3. حلقه و پس‌زمینه **نباید هم‌آلفا** باشند: تفکیک زرد/نارنجی/قرمز عمدتاً از **حلقه** می‌آید.
4. `trend` و `ISS` باید از **یک تابع مشترک** جهت بگیرند، وگرنه متناقض می‌شوند (باگ کانادا).

### ۹٫۳) اعداد سنجیده‌شده (CIE76 ΔE روی پس‌زمینهٔ مؤثر)

| جفت | ΔE | نتیجه |
|---|---|---|
| زرد ↔ نارنجی | **۲۸٫۱** | تفکیک خوب |
| نارنجی ↔ قرمز | **۲۱٫۷** | تفکیک خوب (قبل از اصلاح: ۱۵٫۲ ✗) |
| زرد ↔ قرمز | ۴۸٫۶ | عالی |
| سبز ↔ زرد | ۲۸٫۵ | خوب |

**کنتراست (AA):** متن مقدار روی سطح خودش **≥ ۴٫۹** · برچسب **≥ ۶٫۶** — ۱۲/۱۲ ترکیب (۴ وضعیت × ۳ جهت) و ۱۷/۱۷ کشور بررسی شده.

## ۱۰) گارانتی‌ها و ناهم‌تغییرها (Invariants)

1. **Trend ↔ ISS هم‌جهت‌اند** (هر دو از `recentDirection`) — بررسی خودکار: ۱۷/۱۷ ✓
2. **رنگ متن ISS فقط سه حالت** (سبز/قرمز/سفید) و **هرگز** نارنجی/صورتی نمی‌شود.
3. **هیچ داده‌ای اختراع نمی‌شود:** گپ فقط حاشیه‌نویسی (P4) · سری پله‌ای تجمیع نه درون‌یابی (P3) · سری نرخ محاسبه نمی‌شود.
4. **زوم/اسکرول کاربر** با تغییر تم ریست نمی‌شود (`applyOptions`).
5. **رنگ لجند و بج‌ها** از همان تم چارت می‌آید، نه تم سایت.

| مورد | توضیح |
|---|---|

| تم روشن | `valueUp/Down/Flat` در پالت روشن تُن تیره دارند؛ اگر تم روشن را برای تورم فعال کردید، ۱۲ ترکیب کنتراست را دوباره بسنجید |
